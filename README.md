# AB

تطبيق مراسلة بواجهة سوداء مهيأة للهواتف، يدعم إنشاء حساب أو تسجيل الدخول باسم مستخدم وعبارة سرية، ولا يطلب رقم هاتف أو بريد إلكتروني.

## تشغيل المشروع

ثبّت الحزم بواسطة `pnpm install` ثم شغّل بيئة التطوير بواسطة `pnpm dev`. للتحقق من الأنواع استخدم `pnpm check`، ولتشغيل الاختبارات استخدم `pnpm test`.

## إعداد الأسرار

لا تُنشئ ملف `.env` داخل المشروع ولا تضع أي مفتاح في الواجهة أو في Git. أضف القيم التالية من لوحة الأسرار في بيئة الاستضافة:

| الاسم | الاستخدام |
|---|---|
| `AB_ACTIVATION_CODE` | رمز تفعيل مركزي؛ يتحقق منه الخادم قبل إنشاء حساب أو تسجيل الدخول. |
| `FIREBASE_PROJECT_ID` | معرّف مشروع Firebase من ملف Service Account. |
| `FIREBASE_CLIENT_EMAIL` | بريد حساب خدمة Firebase. |
| `FIREBASE_PRIVATE_KEY` | المفتاح الخاص الكامل لحساب خدمة Firebase. |
| `CLOUDINARY_CLOUD_NAME` | اسم Cloud في Cloudinary. |
| `CLOUDINARY_API_KEY` | مفتاح API للخادم. |
| `CLOUDINARY_API_SECRET` | السر السري لـCloudinary؛ لا يخرج من الخادم. |

## سلوك الوصول

بوابة التفعيل تتحقق من الرمز على الخادم بتوقيت ثابت قبل السماح بإنشاء حساب أو دخول حساب قائم. تخزّن قاعدة البيانات hash لعبارة السر فقط، ولا تخزّن الرمز المركزي أو العبارة السرية بصيغتها الأصلية. عند الاشتباه بعبث أو فقدان جهاز، يكون الإجراء الصحيح هو إبطال الجلسة أو الجهاز ومنع الطلبات اللاحقة من الخادم؛ لا يقوم التطبيق بمحاولة التحكم باتصال شبكة المستخدم.

## Firebase وCloudinary

تم التحقق من حساب خدمة Firebase وأسرار Cloudinary عبر طلبات خادمية خفيفة. استخدم Firebase للهوية والبيانات التي لا تحتوي أي نص رسائل صريح. أما Cloudinary فيستقبل الملفات بعد تشفيرها على الجهاز فقط؛ ينشئ الخادم توقيع الرفع ولا يرسل `API_SECRET` إلى المتصفح.

> لا يدّعي هذا المشروع تنفيذ بروتوكول E2EE مدققاً بعد. قبل الإطلاق الفعلي، أضف بروتوكول تشفير مستقل ومدقق، وتخزين مفاتيح محلياً عبر Capacitor، وآلية جلسات موقعة كاملة لكل جهاز.
